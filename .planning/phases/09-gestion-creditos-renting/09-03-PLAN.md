# Plan 9-3: Server Actions core — requireActor, ledger add-only, creditos y clientes_credito

## Code Patterns (Model Resilience)

- `src/app/actions.ts:1` — `'use server'` + zod (`safeParse`, retorno
  `{ success, errors?, message? }`) + Admin SDK vía `getDb()`.
- `src/lib/firebase-admin.ts` — `getDb()` y `getAdminAuth()`.
- `src/lib/actions/quotation.ts:8` — `runTransaction` sobre `configuracion/counters`
  (SSOT de correlativos; añadir `creditoCount`/`creditoYear` con `{ merge: true }`).
- `src/types/creditos.ts` y `src/lib/actions/creditos-calc.ts` (plan 09-01).
- `src/context/AuthContext.tsx:126` — el cliente provee `{ uid, idToken }`; el action
  NUNCA invoca `useAuth()`.

## Conventions

- **OVERRIDE #4:** el ledger se escribe EXCLUSIVAMENTE con `add()`. PROHIBIDO
  `batch.set()`/`set()`/`update()`/`delete()` sobre `historial_auditoria`.
- **OVERRIDE #3:** `requireActor` usa `getAdminAuth().verifyIdToken(idToken)`; el `uid`
  verificado —NO el enviado— es `registrado_por` (anti-spoofing).
- Tipos numéricos: `moneySchema = z.coerce.number().finite().min(0)` (Float/double);
  `intSchema = z.coerce.number().int().min(0)` (Int64). Rechazar `NaN`/`Infinity`.
- `celular` se normaliza a 12 dígitos con prefijo `57`; tolerar legacy 10 dígitos
  (`"3001234567"`); si no es normalizable, fallo explícito (prohibido null-masking).
- `fecha_registro` de `clientes_credito` y `creditos` se preserva en UPDATE.
- Prohibido `delete()` físico: baja = `activo=false` + `motivo_baja` + `fecha_baja` +
  `baja_por` (ledger `SOFT_DELETE`).
- Zero-Silent-Failures: cada `catch` con `console.error` contextual.
- `revalidatePath('/admin/creditos'...)` tras cada mutation.
