# Plan 9-2: Reglas Firestore — bloqueo de writes de cliente e inmutabilidad financiera

## Objective

Añadir a `firestore.rules` las reglas de las 6 colecciones del módulo: lectura
autenticada y **bloqueo total de escrituras de cliente** (`allow write: if false`) en
las 5 operativas y en `historial_auditoria`. La base de datos rechaza así cualquier
`delete` (Sección 2.C del Documento). Todas las escrituras viajan por Server Actions con
Admin SDK, que ignora las reglas. Gate C2 antes del deploy.

## Code Patterns (Model Resilience)

- `firestore.rules` — sintaxis `rules_version = '2'`; los `match` existentes NO se tocan.
- `src/lib/firebase-admin.ts` — `getDb()` usa ADC e **ignora** `firestore.rules`.
- `src/middleware.ts` — protege `/admin/*` vía cookie `__session`.

## Conventions

- **Gate C2:** antes de `firebase deploy --only firestore:rules`, emitir por escrito la
  constancia de ausencia de writer legítimo client-SDK sobre las 6 colecciones.
- No alterar reglas preexistentes (paridad 1:1 del resto del archivo).
- Zero-Silent-Failures: todo fallo de deploy se registra con `console.error` y payload.
