# Plan 9-4: Server Actions financieras

## Objective

Crear `src/app/admin/creditos/financiero-actions.ts` (`'use server'`) con el alta/edición
y baja lógica de las 3 colecciones financieras, reutilizando `requireActor` y
`appendAuditoria` de `actions.ts`. Regla de Negocio A: comisión y neto se calculan en
SERVIDOR con `calcularComision` (nunca se confía en valores del cliente). Regla M3:
remisiones con máquina de estados `pendiente → recibido`. Prohibido `delete()` físico.

## Code Patterns (Model Resilience)

- `src/app/admin/creditos/actions.ts` (09-03) — `requireActor`, `appendAuditoria`,
  `moneySchema`, patrón `{ success, errors?, message? }`, `revalidatePath`.
- `src/lib/actions/creditos-calc.ts` (09-01) — `calcularComision`.
- `src/types/creditos.ts` — `PagoYMulta`, `PagoInversor`, `RemisionDinero`.

## Conventions

- Comisión/neto se RECALCULAN en servidor leyendo `creditos.condiciones` del
  `id_credito`; si el payload trae `valor_comision`/`valor_neto_empresa`, se descartan.
- `motivo` obligatorio cuando `tipo_transaccion === 'multa'` (refine zod).
- `nota_credito` (Sección 4) admite `valor_pagado_cliente` negativo; comisión 0;
  neto = valor (negativo). Es el único mecanismo de ajuste contable.
- Whitelist estricta: cada action solo acepta claves de su interfaz (Faraday Cage).
- `id_credito` verificado existente y `activo===true`; si no, fallo explícito.
- Zero-Silent-Failures + `revalidatePath` por ruta.

       valor_pagado_cliente: z.coerce.number().finite(),
       tipo_transaccion: z.enum(['pago_cuota','multa','nota_credito']),
       metodo_pago: z.enum(['efectivo','transferencia','tarjeta','pse']).optional(),
       referencia: z.string().optional(), motivo: z.string().optional() })
       .refine(d => d.tipo_transaccion !== 'multa' || (d.motivo ?? '').trim().length > 0,
       { message: 'La multa exige motivo', path: ['motivo'] })
       .refine(d => d.tipo_transaccion === 'nota_credito' || d.valor_pagado_cliente >= 0,
       { message: 'Solo la nota crédito admite valor negativo', path: ['valor_pagado_cliente'] })`.

       `fecha_registro` server; `appendAuditoria` `CREATE` con los valores calculados
